# Three-application development pilot

Run each of two tasks per application in fresh browser contexts across EN/DE/FR for IT-Tools and EN/ES/FR for PDF.js and Kiwix JS, 1280/768/375/320 CSS px, and native versus the inherited WCAG-inspired text-spacing intervention. Total 144 intended tasks. Fixed 900 px height, DPR 1, light theme, blocked external requests. Capture labels and pre/post screenshots. Use no accounts and no remote archives. Kiwix starts in its built-in Restricted mode with service workers blocked. Functional assertions and pre-action geometry signals are separate. A timeout is recorded with its failing step and has no defect label.

- IT-Tools. Navigate to Token generator through the command palette. Separately refresh a generated token on its tool page.
- PDF.js. Find “TraceMonkey” in the bundled sample. Separately advance to page two.
- Kiwix JS. Set dark appearance from settings. Separately open the usage section from About.

Rank the risk baseline in advance by increasing width, spacing first at equal width, then the first non-English locale, FR, EN. Compare twelve settings per task against the fixed pairwise checkerboard and 500 reproducible uniform draws of twelve settings. Count screen-positive configurations separately from any validated defects. Record measured full-grid elapsed time. Subset time is a replay sum of per-configuration timings, not a timed subset run. Human reviewers must adjudicate candidate families and sampled negatives before computing defect-family recall or false alarms. The fixed risk heuristic does not learn from outcomes. Any future model must be evaluated on held-out applications.
